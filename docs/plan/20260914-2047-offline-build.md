## Context

- mica-build's `tools/local-pins.sh <repository> <checkout>` reads
  `<checkout>/_out/debs/<arch>/pool/*.deb` and requires
  `_out/debs/<arch>/SHA256SUMS` to list exactly `pool/<archive>` at those
  digests; mica-core and mica-boards write that layout plus `Packages`.
- mica-podman writes `_out/debs/<arch>/mica-podman_<version>_<arch>.deb` flat,
  with no index; `tests/package-gate.sh`, `tools/release.sh`, `build.yml` and
  `release.yml` read that path.
- The engine build fetches the pinned upstream tags (tree-hash verified) and
  their Go and Cargo modules; the images come from `build-env-image.lock`. No
  other input exists.

## Proposal

1. `tools/package.sh` writes the archive to `<out>/<arch>/pool/` and indexes
   it beside the pool: `Packages` (`dpkg-scanpackages` in
   `IMAGE_MICA_BUILD_BASE`, no network) and `SHA256SUMS` over `pool/<archive>`.
2. The readers follow: the package gate (one archive under `pool/`, and the
   index matches it), `tools/release.sh`, `build.yml` (the artifact is the
   whole `_out/debs/<arch>`) and `release.yml`. Release assets are unchanged.
3. `tools/offline.sh`, run by `make offline`: refuses a dirty tree, builds the
   engine and packs it for amd64 and arm64 (`build.sh`, `tools/package.sh`),
   refuses a tree that became dirty during the build, and prints the pool,
   `Packages` and `SHA256SUMS` of each architecture.
4. `tests/offline-test.sh` (stub build and pack, offline) joins `make check`:
   dirty refusal before any build, both architectures in order, the printed
   paths. README and changelog.

## Risks

- Local arm64 builds on an amd64 host run emulated and take long.
- The upstream sources and modules are still fetched from their origins (the
  pins already in the tree); an increment with vendored sources is out of scope.
